Working principles

Approach and
philosophy

Four rules I’ve learned the hard way. They hold from the first napkin sketch to the last green checkmark.

01

Start with the problem, not the pixels

A blank artboard is a trap. I start in the mess — interviews, constraints, the awkward edge cases nobody wants to name — and open Figma only once I know what I’m actually solving.

02

Design in systems, not screens

Draw the button once, then never again. Tokens, components and rules that keep a product honest as it grows — and land in engineering without a novel-length spec.

03

Ship, measure, refine

A shaky v1 in real hands out-teaches a flawless prototype every time. Put it live, read the data, cut what’s wrong, go again.

04

Code is part of the design

I write the front-end myself, so the last five percent — the easing curve, the half-pixel, the frame that drops — reaches production instead of dying in handoff.
