Nothing is happening

A good hour looks like this — and that’s the hard part.

Most of a shift is quiet. The dashboard’s real job is to let you confirm “all clear” in a glance and look away. Every number leads with a verdict, and every number is a link back to the device it came from.

  1. Verdict, not value — “Good”, “Operational”, “3 critical” sit on the tiles before you read a single figure.
  2. One colour system — green / amber / red mean the same thing on the tile, the node, the alert and the log. Learn it once.
  3. The path is always visible — ISP → firewall → router → core → servers, drawn live, so a break has a place on screen.
  4. Tap any figure — a CPU number, an alert count, a traffic spike lands you on the device, terminal ready. No dead ends.

Why the red was worth trusting.

That took four minutes because the alert was real. NMS never jumps a device straight to Critical — it climbs a ladder, threshold by threshold, each rung with its own notice. Red means tried, escalated, still bad — not “one packet was slow”. It climbs on its own below — hover any rung to hold it there.

  1. Online every metric inside threshold
  2. Warning one soft threshold crossed — latency 45ms, CPU 80%
  3. Degraded the condition holds, or a second metric slips
  4. Critical a hard threshold breaks — ICMP timeout, uptime < 50%
  5. Offline 5 consecutive probes miss over 30 seconds

A small job to do

Everything you need to fix it is in the drawer — not another app.

Spotting a failure is half the job. In the old tool the other half meant switching apps. NMS keeps the terminal, ping, restart, config and logs on the device page itself. Pull a tab.

Terminal

A shell on the device, in the device page

The connection string is shown and copyable, the session opens inline, common verbs are hinted. No separate client, no hunting for the IP — it’s already the device you were looking at.

Reachability

Is it dead, or just slow?

Replies stream in one line at a time, then collapse to a three-number verdict. Two of four means flapping; zero means roll the truck. That decides acknowledge vs. escalate.

Disruptive

The action that interrupts service, treated like it

An amber warning states the cost up front. Soft restart is pre-selected with its downtime estimate; Hard is quieter. Confirm stays disabled until you tick “I understand this causes an interruption”.

Per-device

Thresholds that belong to the device, not the tool

Polling interval, CPU and memory warning levels, and which monitors run — all set per device across four tabs. Reset to defaults is always one click away, so tuning is never a trap.

Guided

A first-responder checklist, automated

Connectivity, gateway, DNS, port scan, cable integrity — each runs in order and reports pass or issue detected. It turns “where do I even start” into a list that starts itself.

History

The last hour of the device, in its own words

Severity filters up top, colour on the left edge, timestamps aligned so a pattern shows — latency → failed gateway → timeout → reconnecting. The story of the outage, not just its current line.

Before you hand over

What you leave for the next shift — and the auditor.

A regulated network has to produce uptime, alert-response times, security events and bandwidth trends on demand. The report flow is a three-step wizard: pick a type, set the window, generate now or schedule.

Three steps, one choice each

Type → configuration → options, with the progress bar always visible and Back always live. Schedule later sits beside Generate now, so recurring compliance reports set themselves.

  • Six types out of the box, including a Security Audit (firewall hits, failed logins, IDS/IPS) and a build-your-own Custom report.
  • The library shows author, size and download count — the report pulled 42 times is obviously the one that matters.
  • Share makes a tokenised link with an expiry and optional password, or sends it by email — original permissions kept.
